The `ShippingService` class (accessed via `client.shipping`) prices delivery for an address, lists a store's delivery rates, returns live carrier options, and tracks parcels.

## How an address is priced

A store's delivery rates are its delivery zones, its distance rates and its "everywhere else" rate. An address is priced by:

1. **The first zone that contains it** — lowest `priority` first, then the zone created first.
2. **Otherwise, the distance rate whose range contains its distance from the store.** A range includes its `min_distance_meters` and stops just before its `max_distance_meters`, so `0–10 km` and `10–50 km` share the 10 km point without overlapping.
3. **Otherwise, the "everywhere else" rate.** When the store has zones or distance rates but no "everywhere else" rate, an address outside them is not delivered to, and `calculateShipping` answers `400 shipping_not_deliverable`.

A matched rate is free when the order reaches its free-delivery threshold. A store with no delivery rates at all charges nothing through them (`applied_rule: none`, `configured: false`). Every amount is in the store's own currency, returned as `currency`.

## Methods

### `getShippingZones`

Retrieve the store's delivery rates: active distance rates, active delivery zones, and the "everywhere else" rate. Useful for showing delivery coverage or likely costs early in the shopping journey.

```typescript
const { currency, pricing_tiers, delivery_zones, everywhere_else } = await client.shipping.getShippingZones();
```

```json Response
{
  "currency": "USD",
  "pricing_tiers": [
    { "tier_name": "Local (within 10 km)", "min_distance_meters": 0, "max_distance_meters": 10000, "delivery_fee": 5.99, "free_delivery_threshold": 75, "is_active": true, "priority": 1 },
    { "tier_name": "Metro (10–50 km)", "min_distance_meters": 10000, "max_distance_meters": 50000, "delivery_fee": 9.99, "free_delivery_threshold": 150, "is_active": true, "priority": 2 }
  ],
  "delivery_zones": [],
  "everywhere_else": { "delivery_fee": 29.99, "free_delivery_threshold": null }
}
```

`everywhere_else` is `null` when the store has none. The response is cached for up to 60 seconds and carries an ETag; `calculateShipping` and order creation always read the current rates.

### `calculateShipping`

Calculate the delivery charge for an address and order total.

<CodeGroup>

```typescript Via Coordinates
// Exact coordinates give the most precise match (recommended).
const shipping = await client.shipping.calculateShipping({
  requestBody: {
    latitude: 40.6782,
    longitude: -73.9442,
    order_total: 50
  }
});
```

```typescript Via Place Name
// A human-readable address or landmark; Galactic Core resolves it to coordinates.
const shipping = await client.shipping.calculateShipping({
  requestBody: {
    place_name: "Brooklyn, New York",
    order_total: 50
  }
});
```

</CodeGroup>

```json Response
{
  "fee": 9.99,
  "currency": "USD",
  "zone_name": null,
  "tier_name": "Metro (10–50 km)",
  "distance_meters": 18432,
  "is_free": false,
  "free_threshold": 150,
  "configured": true,
  "reason": "Metro (10–50 km)",
  "applied_rule": "distance",
  "rate_source": "tier",
  "coordinates": { "latitude": 40.6782, "longitude": -73.9442 }
}
```

<Note>
  `order_total` is the order's merchandise total in the store's currency (e.g. `50` = $50.00), **not** a
  minor-unit (cents) value — the line totals after any discount. It decides whether the order reaches
  the matched rate's free-delivery threshold.
</Note>

**Response Fields:**

| Field | Description |
| :--- | :--- |
| `fee` | The delivery charge, in `currency`. `null` only on a carrier-options-only request. |
| `currency` | The currency of `fee` and `free_threshold` — the store's own. |
| `applied_rule` | Which rate priced the address: `zone`, `distance`, `fallback` (the "everywhere else" rate) or `none` (no delivery rates, or a carrier-options-only request). |
| `rate_source` | Which source produced the result: `zone`, `tier`, `fallback`, `shippo`, `custom` or `none`. |
| `is_free` | `true` when no delivery charge applies to this order. |
| `free_threshold` | The order total from which the matched rate delivers free, or `null`. |
| `configured` | Whether the store has any delivery rates. |
| `zone_name` / `tier_name` | The zone or distance rate that priced the address, when one did. |
| `distance_meters` | Distance from the store to the address, when it was measured. |
| `coordinates` | The resolved location, including when you sent a `place_name`. |

### Live carrier rates (multi-carrier)

When the store has a carrier account connected, or its own custom shipping extension, send a destination `address_to` **and** a `parcel` to also receive live carrier options in `rates[]`. Each option carries its `source` — the store's carrier account (`shippo`) or its custom shipping extension (`custom`).

```typescript
const quote = await client.shipping.calculateShipping({
  requestBody: {
    latitude: 40.748, longitude: -73.985, order_total: 120,
    address_to: { street1: '350 5th Ave', city: 'New York', state: 'NY', zip: '10118', country: 'US' },
    parcel: { length: '10', width: '8', height: '4', distance_unit: 'in', weight: '2', mass_unit: 'lb' },
  },
});
```

To request carrier options only, send `address_to` and `parcel` with no coordinates or place name. The store's own rate is then not priced (there is no location to price it from), so `fee` is `null` and `applied_rule` is `none`. A store with no carrier connected answers that request with `400 provider_not_configured`.

To order with a carrier option, pass its `rate_id` as `shipping_rate_id` and its `source` as `shipping_rate_source` on `createOrder` (with `shipping_parcel` for a custom-extension option). The option is fetched again from its source and checked before it is charged.

<Note>
  Buying a shipping label is done by the merchant from their admin — it charges the merchant's carrier
  account, marks the order shipped, and emits `order.shipped` — so there is no SDK method for it. From a
  storefront you quote rates (`calculateShipping`) and track parcels (`trackShipment`).
</Note>

### `trackShipment`

Returns live tracking status for a parcel by carrier and tracking number, for rendering the status timeline inside your own UI. A secret key tracks any parcel on the store's carrier account; a publishable key tracks only a tracking number that is on one of the store's own orders, so a storefront can show a shopper their own parcel.

```typescript
const status = await client.shipping.trackShipment({ carrier: 'usps', number: order.tracking_number });
```

```json Response
{
  "carrier": "usps",
  "tracking_number": "9400111899223197428490",
  "status": "TRANSIT",
  "status_details": "Arrived at USPS Regional Facility",
  "eta": "2026-08-07T17:00:00Z",
  "history": [
    {
      "status": "TRANSIT",
      "status_details": "Arrived at USPS Regional Facility",
      "status_date": "2026-08-04T09:12:00Z",
      "location": { "city": "Springfield", "state": "VA", "country": "US" }
    },
    {
      "status": "TRANSIT",
      "status_details": "Accepted at USPS Origin Facility",
      "status_date": "2026-08-03T18:40:00Z",
      "location": { "city": "Richmond", "state": "VA", "country": "US" }
    }
  ]
}
```

<Tip>
  The lightest way to let a shopper track is to **link to the carrier's own tracking page** — no API
  call. When the label is bought, the carrier tracking URL is saved on the order at
  `shipping_metadata.shippo.tracking_url`; render it as a "Track your package" link. Use
  `trackShipment` only when you want the status shown natively in your storefront.
</Tip>

## Response Codes

All three methods accept **publishable** and **secret** keys. `calculateShipping` uses `POST` purely to carry a structured request body — it is read-only.

### `getShippingZones` (`GET /v1/shipping/zones`)

| Code | Meaning |
| :--- | :--- |
| `200` | Delivery rates returned. |
| `304` | Not modified (you sent a matching `If-None-Match`). |
| `401` | Invalid or missing API key. |
| `403` | Forbidden (e.g., key disabled or store suspended). |
| `429` | Rate limit exceeded. |
| `500` | Internal server error. |

### `calculateShipping` (`POST /v1/shipping/calculate`)

| Code | Meaning |
| :--- | :--- |
| `200` | Charge calculated and returned. |
| `400` | `invalid_request` (a location outside -90..90 / -180..180, an `order_total` that is not a number of zero or more, or no location at all), `geocoding_failed` (a `place_name` could not be found), `shipping_not_deliverable` (the store does not deliver to the location), or `provider_not_configured` (a carrier-options-only request to a store with no carrier connected). |
| `401` | Invalid or missing API key. |
| `403` | Forbidden (e.g., key disabled or store suspended). |
| `429` | Rate limit exceeded. |
| `500` | Internal server error. |

### `trackShipment` (`GET /v1/shipping/tracking/{carrier}/{number}`)

| Code | Meaning |
| :--- | :--- |
| `200` | Tracking status returned. |
| `400` | Invalid carrier or tracking number. |
| `401` | Invalid or missing API key. |
| `404` | With a publishable key, the tracking number is not on any of the store's orders. |
| `429` | Rate limit exceeded. |
| `502` | The carrier's tracking service could not be reached (`tracking_unavailable`). |
