# Galactic Core

Galactic Core exposes a production retail system — inventory, orders, accounting, payments, customers —
through versioned REST endpoints, so an application can run commerce without implementing it.

## What the API provides

<CardGroup cols={2}>
  <Card title="Operational Depth" icon="layer-group">

  </Card>
  <Card title="Global Velocity" icon="bolt">
    Globally distributed delivery with fast response times and aggressive caching for read-heavy endpoints.
  </Card>
  <Card title="Unified Logic" icon="puzzles-piece">
    Centralized business rules, so a sales channel does not carry its own copy of them.
  </Card>

## Performance & Reliability

- **Edge-served responses**: reads are answered from the network edge, close to the caller.
- **Idempotency**: write operations such as order creation accept an idempotency key, so a retry cannot produce a duplicate.
- **Field filtering**: most list endpoints accept a `fields` parameter, which cuts response size by 50–90%.

## Authentication

All API requests carry an API key in the `Authorization` header. There are two key types:

- **Publishable keys (`pk_...`)**: safe for client-side use in websites and mobile apps, and limited to reads and the writes a shopper makes on their own behalf.
- **Secret keys (`sk_...`)**: full read/write access, for backend-only environments.

```bash
Authorization: Bearer tybrite_sk_live_YOUR_KEY
```
