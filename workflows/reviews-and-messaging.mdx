title: "Shopper Engagement: Wishlist, Reviews & Messaging"
description: "Everything that keeps a shopper engaged around a purchase — saving items to a wishlist and moving them to the cart, writing and voting on reviews (including the duplicate-review conflict), and running a real-time support conversation (both realtime modes, plus edit/delete)."
---

One signed-in shopper moves through the three surfaces that surround a purchase: they save the Watch
to their wishlist and later move it into the cart, they review the product they bought, and they open
a support thread about the order. Along the way come the atomic wishlist-to-cart move, a second
review meeting a `409`, a deleted message, and the two realtime connection shapes.

Every call here acts on a signed-in shopper's own data, so it pairs an API key with the shopper's
session token in `xAuthToken`. [Workflow Examples](/workflows/introduction) has the client setup, and
[Storefront Checkout](/workflows/storefront-checkout#3-signing-the-shopper-in) covers minting that
session token. One shopper — Jane Doe, customer `9489529e-69b0-4e84-bea7-62c499085bd9` — and one
product, the Samsung Galaxy Watch 6 (`0186665f-…`, variant `e98631a9-…`), carry throughout.

<Info>
  Wishlist, review, and messaging writes are browser-origin storefront writes, so the publishable
  client covers them; the shopper's `xAuthToken` is what proves ownership. Moderating reviews and
  replying from the store side happen in the merchant admin and are not API actions.
</Info>

## Wishlist

The shopper is not ready to buy, and saves the Watch for later. Wishlists are always
customer-scoped, so every call carries `customer_id` and the matching `xAuthToken`.

### 1. Adding to the wishlist

`addToWishlist` saves a variant and returns the refreshed wishlist (`201 Created`). Its items carry
`product_price`, the price quoted at the time of saving — a field the cart's items do not have.

```typescript
const wishlist = await storefront.cartWishlist.addToWishlist({
  xAuthToken: session.access_token,
  requestBody: {
    variant_id: 'e98631a9-7852-4fe8-8efe-988935d5922a',
    customer_id: '9489529e-69b0-4e84-bea7-62c499085bd9',
  },
});
```

```json Response
{
  "items": [
    {
      "id": "2dac3a23-afec-4b6a-a369-e7bdb1f3bc32",
      "product_id": "0186665f-f0a1-4c79-976a-919b5b1c2daa",
      "variant_id": "e98631a9-7852-4fe8-8efe-988935d5922a",
      "product_name": "Samsung Galaxy Watch 6",
      "variant_name": "Default",
      "variant_attributes": {},
      "product_sku": "SAM-WATCH-6-44-0186",
      "product_price": 299,
      "thumbnail_url": "https://cdn.tybritelabs.com/.../samsung-galaxy-watch-6.jpg"
    }
  ]
}
```

<Note>
  A variant can be saved once per customer. Adding the same variant again returns `409 Conflict`
  (`{ "error": { "code": "conflict", "message": "Item already exists in wishlist" } }`) rather than
  creating a duplicate, which makes the `409` itself a reliable "already saved" signal.
</Note>

### 2. Reading the wishlist

`getWishlist` lists the customer's saved items in the same item shape as the add response.
`customer_id` is required, as anonymous wishlists are not supported.

```typescript
const { items } = await storefront.cartWishlist.getWishlist({
  xAuthToken: session.access_token,
  customerId: '9489529e-69b0-4e84-bea7-62c499085bd9',
});
// → items[0].product_name === 'Samsung Galaxy Watch 6', items[0].product_price === 299
```

### 3. Moving a saved item to the cart (atomic)

The shopper decides to buy. `moveWishlistToCart` is one atomic step: it validates stock, adds the
item to the cart or merges it with an existing line, removes it from the wishlist, and returns the
refreshed cart. The response echoes `removed_wishlist_item_id` to identify the saved item that is
gone, and the returned cart item carries a new id, being a cart row rather than the wishlist row.

```typescript
const cart = await storefront.cartWishlist.moveWishlistToCart({
  xAuthToken: session.access_token,
  requestBody: {
    wishlist_item_id: '2dac3a23-afec-4b6a-a369-e7bdb1f3bc32',
    customer_id: '9489529e-69b0-4e84-bea7-62c499085bd9',
    quantity: 1,
  },
});
```

```json Response
{
  "success": true,
  "message": "Item moved from wishlist to cart",
  "removed_wishlist_item_id": "2dac3a23-afec-4b6a-a369-e7bdb1f3bc32",
  "items": [
    {
      "id": "845e8724-a3dc-432c-9771-26a4173ec48c",
      "product_id": "0186665f-f0a1-4c79-976a-919b5b1c2daa",
      "variant_id": "e98631a9-7852-4fe8-8efe-988935d5922a",
      "product_name": "Samsung Galaxy Watch 6",
      "variant_name": "Default",
      "variant_attributes": {},
      "product_sku": "SAM-WATCH-6-44-0186",
      "quantity": 1
    }
  ]
}
```

### 4. Removing a saved item

A shopper discarding a saved item instead reaches `removeFromWishlist`, which deletes it by id. The
`customer_id` query param is required, which is what scopes the delete to its owner.

```typescript
const removed = await storefront.cartWishlist.removeFromWishlist({
  xAuthToken: session.access_token,
  id: '2dac3a23-afec-4b6a-a369-e7bdb1f3bc32',
  customerId: '9489529e-69b0-4e84-bea7-62c499085bd9',
});
// → { success: true, message: 'Item removed from wishlist' }
```

```json Response
{ "success": true, "message": "Item removed from wishlist" }
```

<Tip>
  The wishlist sits alongside the cart in the same `cartWishlist` service. From here the Watch goes
  into the [storefront checkout](/workflows/storefront-checkout) and is paid for, and the shopper
  returns to review it.
</Tip>

## Reviews

The Watch has arrived and the shopper wants to review it. Reviews start hidden and become public only
once the merchant approves them.

### 5. Submitting a review (starts `pending`)

`submitReview` creates the review with `status: "pending"`, and it appears in public listings only
after the merchant approves it in their admin. An `order_id` belonging to the shopper flags the
review `verified_purchase: true`.

```typescript
const { review } = await storefront.reviews.submitReview({
  xAuthToken: session.access_token,
  requestBody: {
    product_id: '0186665f-f0a1-4c79-976a-919b5b1c2daa',
    rating: 5,
    title: 'Outstanding quality',
    body: 'Exactly as described — fast shipping and great build quality. Would buy again.',
  },
});
```

### 6. The duplicate review → `409 Conflict`

A shopper holds only one non-rejected review per product, so a second review from Jane for the same
Watch returns `409`. The resolution is editing the existing review rather than retrying the submit.

```typescript
try {
  await storefront.reviews.submitReview({
    xAuthToken: session.access_token,
    requestBody: {
      product_id: '0186665f-f0a1-4c79-976a-919b5b1c2daa',
      rating: 4,
      title: 'Changed my mind a little',
      body: 'Still good, but the battery drains faster than I expected.',
    },
  });
} catch (err) {
  // err.status === 409 — the shopper already reviewed this product
}
```

```json Response (409)
{
  "error": {
    "code": "conflict",
    "message": "You have already reviewed this product"
  }
}
```

### 7. Listing approved reviews (public, with summary)

Once the merchant approves the first review, `listReviews` backs the product page's review section.
On a publishable key it returns only `approved` reviews and always includes a `summary` block —
average rating plus star distribution. This is public catalog data, so no customer token is involved.

```typescript
const { reviews, summary } = await storefront.reviews.listReviews({
  productId: '0186665f-f0a1-4c79-976a-919b5b1c2daa',
});
// → summary.average_rating === 5, summary.five_star === 1
```

### 8. Marking a review helpful

Upvotes let a product page surface the reviews shoppers found useful. Only approved reviews accept
votes, and there is no built-in de-duplication, so per-shopper voting state belongs in your own UI.

```typescript
const { helpful_count } = await storefront.reviews.markReviewHelpful({
  id: '11bc03d9-d1cb-4833-b9d2-f0b016104cde',
});
// → helpful_count === 1
```

```json Response
{ "helpful_count": 1 }
```

<Note>
  A shopper can remove their **own** review with
  `storefront.reviews.deleteReview({ id, xAuthToken: session.access_token })` — it returns
  `{ "success": true, "message": "Review deleted" }`. Deleting someone else's review returns `403`.
</Note>

## Messaging

The shopper opens a support thread about the order, and it stays live so the store's replies arrive
without polling.

### 9. Starting a conversation

`createConversation` opens a thread and posts the shopper's first message in one call. `thread_type`
classifies the inquiry (`general`, `order_inquiry`, `product_inquiry`, `support`, `complaint`,
`delivery`, `return`, `refund`, `technical`). A `customer_id` comes with the matching `xAuthToken`.

```typescript
const { thread } = await storefront.messaging.createConversation({
  xAuthToken: session.access_token,
  requestBody: {
    customer_id: '88ad3683-d291-4c70-8f8b-9903a42bde1b',
    customer_name: 'Jane Doe',
    customer_email: 'jane.doe@example.com',
    subject: 'Question about my order',
    message: 'Hi — I placed an order and wanted to check the expected delivery window.',
    thread_type: 'order_inquiry',
  },
});
// → thread.id is the conversation you send follow-ups to
```

```json Response
{
  "thread": {

    "subject": "Question about my order",
    "status": "active",
```

### 12. Editing or deleting a message

A shopper can revise or retract a message they sent. Both calls require a secret key and so run
server-side. `editMessage` rewrites the content and stamps `is_edited: true` plus `edited_at`;
`deleteMessage` soft-deletes — the row stays, marked `is_deleted` and excluded from the default
message list — and returns the `deleted_at` timestamp.

```typescript
const edited = await server.messaging.editMessage({
  xAuthToken: session.access_token,
  id: 'c423c11e-ab5f-40ab-8e17-429a39710d60',
  requestBody: { message_content: 'Hi — checking the delivery window (order ORD-1781955473455).' },
});
```

```json Response
{
  "message": {
    "id": "c423c11e-ab5f-40ab-8e17-429a39710d60",
    "message_content": "Hi — checking the delivery window (order ORD-1781955473455).",
    "is_edited": true,
    "edited_at": "2026-06-20T13:52:41.118+00:00",
    "updated_at": "2026-06-20T13:52:41.118+00:00"
  }
}
```

```typescript
const deleted = await server.messaging.deleteMessage({
  xAuthToken: session.access_token,
  id: 'c423c11e-ab5f-40ab-8e17-429a39710d60',
});
// → { success: true, message_id: '...', deleted_at: '...' } — soft delete, row is hidden not gone
```

```json Response
{
  "success": true,
  "message_id": "c423c11e-ab5f-40ab-8e17-429a39710d60",
  "deleted_at": "2026-06-20T13:53:02.704+00:00"
}
```

### 14. Streaming replies in real time

The `subscribeToThread` helper opens a WebSocket to the thread, delivering the store's replies as
they are sent rather than on a polling interval. The same call covers a shopper who signed in through
Galactic Core and one who signed in through your own identity provider, and it pulls in no extra
packages: it uses the platform `WebSocket`, available in browsers, Deno, Bun, and Node 22+.

```typescript
import { subscribeToThread } from '@tybrite-labs/sdk';

// A shopper signed in through Galactic Core — pass their session token:
const unsubscribe = subscribeToThread({
  apiKey: 'tybrite_pk_live_...',
  threadId: '06084af6-7334-43d6-82c0-935f92335a25',
  authToken: session.access_token,
  onMessage: (msg) => {
    console.log('New message:', msg.message_content);
  },
});

// later, when the shopper closes the thread:
unsubscribe();
```

For a shopper authenticated with your own identity provider, the signed assertion goes in
`externalAuth` in place of `authToken`; everything else is identical:

```typescript
const unsubscribe = subscribeToThread({
  apiKey: 'tybrite_pk_live_...',
  threadId: '06084af6-7334-43d6-82c0-935f92335a25',
  externalAuth: signedAssertion, // your IdP's HMAC-signed identity assertion
  onMessage: (msg) => console.log('New message:', msg.message_content),
});
```

The connection is authorized server-side: the credential is validated and confirmed to be the
thread's participant before the socket is accepted, so a shopper only ever receives **their own**
thread's messages.

<Note>
  A connection managed directly, without the helper, is a WebSocket to
  `GET /v1/messaging/threads/{id}/subscribe` carrying `?api_key=` and either `?auth_token=` or
  `?external_auth=` in the URL, since browsers cannot set request headers on a WebSocket. The server
  pushes one JSON frame per new message:
  `{ "type": "message.created", "payload": { "thread_id", "message" } }`. The text frame `ping` keeps
  an idle connection alive, and the server replies `pong`.

  [Customer authentication](/authentication#customer-session-tokens-xauthtoken) covers bringing your
  own identity provider.
</Note>
